# Token budget policy

The binding constraint is spend, not capability. Design accordingly.

## Rules

1. **Briefs, not dumps.** A specialist receives a question and constraints, not
   the venture folder. If it needs a file, name that file.
2. **Summarise upward.** A manager passing work up sends conclusions and the
   evidence for them, never the raw output.
3. **One tier down first.** Attempt every task at the cheapest plausible tier.
   Escalate only after a visible failure, and record why.
4. **Cap the scan.** Step 1 of the loop is shallow by design. Depth is earned by
   surviving the screen.
5. **No re-reading.** Do not reload files already summarised in this session.
6. **Kill loops.** Two failed attempts at the same subtask stops the thread and
   escalates to a human. No third try.

## Rough allocation

| Stage | Share of cycle budget |
|---|---|
| Scan | 10% |
| Screen | 10% |
| Research | 40% |
| Build | 25% |
| Measure and decide | 15% |

If research is eating the budget, the screen is too loose. Tighten the screen
rather than raising the budget.
